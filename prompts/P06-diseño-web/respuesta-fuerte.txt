2. Código Mejorado (HTML Semántico y CSS Accesible) 

HTML (index.html) 

Al abrir index.html se muestra la página de Asesoría Digital Pro, con un enlace para saltar al contenido principal, una cabecera con navegación y el contenido organizado en secciones semánticas. Carga styles.css para el aspecto visual. Gracias a esa estructura, la página se puede recorrer con el teclado y cada bloque queda identificado en la jerarquía del documento. 

CSS (styles.css) 

Define las variables de color y tipografía en :root y reglas para la cabecera, la navegación, el contenido y el pie. Al aplicarse, la página muestra colores con contraste pensado para WCAG AA y un foco visible en enlaces y botones. Incluye una regla de prefers-reduced-motion que reduce las animaciones para quien lo active en su sistema. No devuelve datos; su resultado es el aspecto visual de la página. 

JavaScript (script.js) 

El script obtiene el botón del menú móvil y el contenedor de navegación y, si ambos existen, escucha el clic en el botón. En cada clic invierte el atributo aria-expanded, de modo que los lectores de pantalla anuncian si el menú está abierto o cerrado. También cierra el menú al pulsar la tecla Escape. Su efecto visible es el cambio de estado del menú; no devuelve ningún valor. 

Lista de Cambios Principales Realizados 

Semántica HTML5: Sustitución de etiquetas genéricas (<div>) por elementos semánticos precisos (<header>, <nav>, <main>, <section>, <article>, <footer>). 

Jerarquía de Encabezados: Se garantizó un único <h1> en la sección principal (hero) y títulos lógicos en orden descendente (<h2>, ###). 

Navegación por Teclado y Enlace de Salto: Se implementó un skip-link para saltar directamente al contenido y un foco visible consistente (outline-offset). 

Accesibilidad en Menús: Inclusión de atributos ARIA (aria-expanded, aria-controls) y soporte para cerrar con la tecla Escape. 

Reducción de Movimiento: Añadido soporte explícito para @media (prefers-reduced-motion: reduce). 

Optimización de CSS: Uso de variables CSS estructuradas y un sistema de espaciado estricto basado en múltiplos de 4px.

# ACCESSIBILITY_REPORT.md - WCAG 2.2 AA Compliance 
 ## 1. Verificación de Etiquetas y Atributos 
 - **Etiquetas de formularios:** Todo input futuro requerirá su etiqueta `<label>` explícitamente vinculada mediante el atributo `for` e `id`. 
 - **Textos alternativos (`alt`):** Se ha validado que los elementos decorativos utilicen `aria-hidden="true"` y que las imágenes informativas lleven descripciones concisas. 
 - **Botones y Enlaces:** Textos claros sin ambigüedades (evitando "haz clic aquí"). Los botones interactivos de control disponen de `aria-label`. 
  
## 2. Navegación por Teclado 
 - **Orden de tabulación:** Lógico y secuencial de izquierda a derecha y de arriba a abajo, siguiendo el flujo visual. 
 - **Enlace "Saltar al contenido":** Implementado al inicio del DOM (`.skip-link`). 
 - **Indicador de foco:** Foco visible personalizado con alto contraste (`outline: 3px solid var(--color-accent)`). 
 - **Trampas de foco (Focus traps):** Ninguna detectada; comportamiento nativo respetado. 
 - **Gestión de eventos de teclado:** El menú móvil responde al atributo `aria-expanded` y la tecla `Escape` cierra correctamente los componentes flotantes. 
  
## 3. Auditoría de Contraste de Color (WCAG 2.2 AA) 
 Todas las combinaciones clave cumplen o superan los requisitos mínimos (Texto normal >= 4.5:1; Texto grande / Componentes UI >= 3:1): 
  
| Elemento / Combinación | Ratio Calculado | Estado (WCAG 2.2 AA) | 
 | :--- | :--- | :--- | 
 | Texto principal (`--color-text`: `#334155`) sobre Fondo (`--color-background`: `#F8FAFC`) | **10.51 : 1** | Aprobado (AAA) | 
 | Títulos (`--color-text-heading`: `#0F172A`) sobre Fondo (`--color-surface`: `#FFFFFF`) | **16.12 : 1** | Aprobado (AAA) | 
 | Botón Principal (Texto blanco sobre `--color-accent`: `#1D4ED8`) | **5.74 : 1** | Aprobado (AA/AAA) | 
 | Enlaces del Footer (`#94A3B8`) sobre Fondo oscuro (`#0F172A`) | **5.21 : 1** | Aprobado (AA) | 
  
- **Uso exclusivo de color:** Ninguna información crítica depende únicamente del color; se acompaña de iconos o tipografía en negrita. 
 - **Prefers-reduced-motion:** Implementada regla global para desactivar transiciones en usuarios con sensibilidad vestibular. 
  
## 4. Metodología de Verificación 
 - **Herramienta automatizada sugerida:** Ejecución local recomendada con **axe-core** (vía extensión de navegador o CLI) y validador oficial del W3C para HTML. 
 - **Verificación manual:** Navegación exclusiva mediante teclado (tecla `Tab`, `Shift+Tab`, `Enter`, `Escape`) y comprobación visual del foco. 

4. Resumen Ejecutivo (Supuestos y Decisiones) 

Supuesto de Caso 1: Al no hallar archivos locales, se diseñó bajo el supuesto de una landing page de servicios corporativos / asesoría. 

Decisión de estructura: Se priorizó el SEO técnico y la accesibilidad estableciendo un único <h1> en el bloque principal (hero). 

Decisión de diseño CSS: Se adoptó una paleta basada en Slate y azul corporativo contrastado para garantizar legibilidad superior a 4.5:1. 

Decisión de interacción: JavaScript se limitó exclusivamente al control del menú móvil desplegable y al evento de cierre con la tecla Escape. 

Decisión de accesibilidad: Se incorporó de serie un enlace de salto (skip link) y propiedades ARIA para lectores de pantalla. 

Decisión de contenidos: Los textos provisionales se marcaron explícitamente como [TEXTO PENDIENTE] para su posterior redacción comercial. 

Decisión de movimiento: Se incluyó la directiva CSS de prefers-reduced-motion por defecto. 

Decisión mobile-first: Estilos de cuadrícula adaptables (grid-template-columns) optimizados para pantallas reducidas. 

Decisión de tipografía: Uso exclusivo de una fuente (Inter) con variantes de peso para mantener la ligereza de carga. 

Decisión de entrega: Se documentaron de forma transparente los informes de diseño y accesibilidad para validación por parte del equipo de control de calidad.
